# Changelog

## 0.8.0 — 2026-10-22

- **项目协调会话**：项目树的项目节点右侧新增「项目会话」按钮，按需在主工作区创建/打开一个普通 DSH 会话（「项目协调台 · <项目名>」），会话映射持久化在 `dsh_session_board_projects` 域。
- 协调会话获得项目范围工具：`project_overview`（分支工作区/运行状态/任务）、`project_assign_task`（只能派到项目内工作区，创建任务会话+首条 brief）、`project_message_session`（向项目内已有会话排队消息）、`project_session_status`。
- 项目内工作会话自动获得 `report_to_coordinator` 工具：可回报进展/阻塞给协调会话，带 taskId 时同时更新任务备注；消息均走官方 `session.prompt`，可在会话日志审计。
- 新增认证路由 `POST /api/session-board/project/coordinator`（按 projectKey 打开/创建协调会话）；项目/任务数据分别落在独立域与 manager 任务表，互不影响。
- 新增项目发现、协调会话生命周期、工具安装与执行、worker 回报、路由与树按钮的测试。

## 0.7.1 — 2026-10-22

- 修正「按项目树」的中文选项文案：0.7.0 只改了英文 `Project tree`，中文分组下拉仍显示「工作区树」。

## 0.7.0 — 2026-10-22

- **项目树分组**：分组方式里的「按项目树」会读取每个工作区的 git `remote.origin.url` 与当前分支，把同一仓库的不同分支工作区收进同一个项目节点，分支名作为副标题显示；点项目/工作区节点可多级展开与折叠。
- 宿主新增只读元数据路由 `GET /api/session-board/workspace-meta`：只探测 `workspaceRegistry` 里登记的路径，2 分钟缓存、最多 400 个、每批 6 个并发，单条 git 探测失败不影响其它工作区；非 git 目录保持原来的路径树分组。
- 客户端启动时后台加载元数据，切换到「按项目树」时会强制刷新；元数据不可用时静默回退到路径树，不影响原有按状态/按工作区视图。

## 0.6.0 — 2026-10-22

- **自动唤醒整体重做**：不再依赖“下一个事件到来时检查、最多每分钟一次”。统一的唤醒调度器带真实定时器，冷却结束时自动补发，不再出现“报错后等到下一次无关事件才提醒、甚至永远不提醒”。
- **按紧急程度分级**：错误（turn 失败/工具报错）约 3 秒去抖、等待处理（aborted/blocked）约 12 秒、普通完成批量 45 秒；进度类事件只更新状态、不唤醒。每类有独立的小时预算（错误/等待 20 次、完成 6 次），超过预算排队到窗口滚动并在面板显示抑制次数。
- **投递确认与重试**：digest 成功交给管理 Agent 后才确认消费；失败保留队列，按 15s→30s→…→120s 退避重试，不再静默丢失。
- **排除自我唤醒**：管理台自身的 `session/event` 与 `agent/status` 被 mux 忽略，避免被自己的 digest 再次唤醒形成循环。
- **可见可控**：抽屉底部新增「自动唤醒」行：开关、待处理数量（错误/等待/完成）、本小时唤醒次数、「立即汇总」按钮；新增认证路由 `POST /api/session-board/manager/wake`（enable/disable/now）。`set_auto_wake` 工具保留。
- **状态持久化**：上次唤醒时间与滚动小时窗口写入 manager domain，宿主重启后预算与节奏不会重置。
- 新增调度器单测、mux 待处理/确认/忽略测试、服务集成测试（投递、自排除、手动唤醒、关闭）与唤醒路由测试。

## 0.5.3 — 2026-10-22

- **归档严格按勾选**：移除子会话自动展开（scope 只包含你勾选的会话），勾了几个归档几个。需要子会话时把它们一并勾选；预览仍会提示“来源缺失的子会话”，但不再把未勾选的子会话算进批次，也不会因此误报“选择已失效”。
- **新增独立的「仅归档」批量动作**：与「预览归档与提炼」并列，只把原文复制到配置的 Wiki 根目录并做 DSH 原生归档，不调用模型、不更新索引；确认面板与按钮文案会明确区分这两种模式（筛选栏原有的「仅归档」视图按钮不变）。
- 移除 0.5.2 的 200 条展开上限与 `SCOPE_TOO_LARGE`：不再自动展开后，50 条勾选上限就是批次的真实上界。
- 宿主的 scope 校验改为“返回集合必须与勾选集合一致”，防止 bridge 多报或漏报时静默归档额外会话。

## 0.5.2 — 2026-10-22

- 修复「选中会话连同子会话超过 50 个时误报选择已失效」：用户勾选上限仍是 50，但展开子会话后的归档范围放宽到 200；超过 200 时返回明确提示「连同子会话超过 200 个，请分批归档」（`SCOPE_TOO_LARGE`），不再显示误导性的“重新勾选并预览”。
- bridge 诊断日志目录自动创建：`~/.dsh-session-board/` 不存在时日志此前写入失败且无提示；现在会创建目录并照常记录 start/fatal/done。
- 宿主的 scope/summary 解析同步新的展开上限，预览与提交不再被旧的 50 总上限截断。

## 0.5.0 — 2026-10-22

- **Wiki 归档引擎自包含**：`wiki-archive.py` / `wiki-synthesize.py` / `wiki-index.py` 随插件发布（`lib/wiki/`），不再依赖 `~/wiki/scripts` 里与插件契约匹配的本地脚本；本地脚本可在设置里切回「本地 wiki scripts」模式继续使用。
- **默认复用当前本地 Wiki**：默认 wiki 根目录 `~/wiki`、SCHEMA 规则 `<wiki 根目录>/SCHEMA.md`、归档状态 `<wiki 根目录>/scripts/.archive-state.json`（与 CLI 归档共用，增量不重复）；页面、状态文件与锁始终写在 wiki 根目录内，不写进插件安装目录。
- 设置页新增「Wiki 归档引擎」分组：Wiki 根目录、SCHEMA 路径、引擎来源（内置/本地）、脚本目录、Python、超时、provider、状态文件与 provider 配置文件均可编辑，保存到宿主插件存储，下一次归档生效；「检查环境」报告引擎脚本、Python、SCHEMA 与状态路径。
- 宿主导出的配置可在 `cordis.patch.yml` 里写部署默认值；用户保存过的配置优先。
- 归档失败不再只给兜底文案：宿主与 bridge 返回具体错误码和诊断详情，面板在错误下方显示原因，完整 traceback/stderr 追加到 `~/.dsh-session-board/wiki.log`；超时可配置（默认 300 秒），scope 只解压一次 transcript。
- 宿主插件存储新增独立 wiki 配置域；旧布局（本地 scripts + `~/wiki` SCHEMA）在未保存任何配置时行为不变。

## 0.4.0 — 2026-10-20

- 新增「管理中心」常驻面板（右侧抽屉）：上半屏是工作区看板，点开工作区后列出会话并支持勾选；下半屏直接嵌入官方聊天，与一个常驻的管理 Agent 对话。
- 管理 Agent 是一个普通 DSH 会话（默认标题「DSH 管理台」，懒创建在 `~/Documents/deepseek-harness/dsh-console` 工作区），可随时冷恢复；只有它会获得管理工具，普通会话看不到。
- 管理工具：`workspace_overview`、`workspace_sessions`、`session_status`、`read_selection`、`assign_task`、`list_tasks`、`update_task`、`report_progress`、`set_auto_wake`。
- 勾选「发送选区」会以一条普通用户消息把选区块交给管理 Agent（走官方 `session.prompt`），选区同时持久化到宿主，作为管理工具的输入。
- 任务板：`assign_task` 在目标工作区创建会话、投递任务说明并登记任务；任务状态由会话事件派生（运行中/出错/等待），也可由管理 Agent 显式更新。
- 宿主新增 epoll 风格的事件多路复用器：折叠 `session/event` 与 `agent/status` 为「全量状态 + 有界就绪队列」，自动唤醒默认关闭，开启后每分钟最多一次、管理员空闲时才投递一条 digest。
- 新增三个已认证 JSON 路由：`GET /api/session-board/manager/state`、`POST /api/session-board/manager/selection`、`POST /api/session-board/manager/task`。
- 兼容性：要求宿主提供 `sessionController`/`workspaceRegistry`/`agents` 服务；缺失时只隐藏管理中心，原看板不受影响。

## 版本约定

每次发布变更使用新的版本号；已发布的标签和安装包不覆盖。兼容性修复递增补丁版本，新增功能递增次版本，不兼容变更显式记录。每个插件独立发布，标签格式为 `<插件名>-v<版本>`。
