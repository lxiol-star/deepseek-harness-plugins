## 0.2.14 — 2026-11-27

子会话挂到"长出它的那张卡"下面。

- 上一版只画主会话的子会话，但**主会话自己派不出子会话**（它只有编排工具），所以那个分组在真实使用里几乎总是空的。真正会长子会话的是**执行器**：它可以 `subagent`，tower 模式也会给它子 agent。
- 现在 `children` 每一项都带 `parentId`：主会话的子会话仍画成「其他子会话 · N」分组；某个执行器的子会话则画在**那张执行器卡内部**（虚线缩进列表，带状态点、标题、来源），归属一眼可见。
- 单测：`runtime.spec` 覆盖"执行器的子会话也在列表里、且 parentId 指向执行器"；`canvas.spec` 覆盖"分组只数主会话的子会话""子会话出现在长出它的那张卡里"。全量 1263 通过 / 6 个既有环境噪声。

## 0.2.13 — 2026-11-27

实测（隔离实例 + 真实模型 + 真跑一次工单）抓出并修掉两处，都是"看起来正常、实际干不了活"的那种。

- **修复：worker 又只剩几个工具了（我 0.2.12 引入的）。** `tower_*` 是全局工具，它们让 `restrict()` 的白名单**非空**，于是"空名单就下手"的保护被绕过，`restrict({allow: ['tower_activate']})` 成功执行并把继承来的 bash/read/write 全藏了——worker 只剩 6 个 `orchestrator_*` 加一个 `tower_activate`，而它会照常"汇报已执行"。现在只有当白名单里**仍包含核心工作工具**（read/write/edit/bash/grep）时才会应用限制，否则只留按名字拒绝的守卫。
- **修复：工单目录是空仓库，需要底座 commit 的工具用不了。** 建工单目录后若它还不是 git 仓库，就用一个临时身份 `git init` 并留一个空提交；已经是仓库的原样不动，没有 git 的宿主保持普通目录、不影响开单。依据是 tower 的原话：`the repository has no commits yet — create an initial commit first`。
- **实机验证**（隔离 home，模型真跑）：worker 25 个工具（bash/read/write 齐）→ `bash -c "echo shell-ok && pwd"` 退出码 0 → 调 `tower_activate` 返回 `Tower mode: ON (base main, checkout main)` 且工作目录出现 `.git` + `.tower/` → 激活后 schema 动态长出 13 个 tower 工具（`tower_status`/`tower_inbox` 已实调成功）。
- 单测：`environment.spec` 新增两条（空目录播种后一个提交、二次播种不变、已有仓原样保留）；全量 1262 通过 / 6 个既有环境噪声。

## 0.2.12 — 2026-11-26

画布上能看见主会话自己开出来的子会话了，而且和工单执行器分得清。

- **两类节点**：「执行器」这一列现在画两批卡片——工单执行器（实线边框、`running` 图标）和**其他子会话**（虚线边框、`user` 图标，另有分组标题「其他子会话 · N」）。子会话卡显示标题、来源（`子 agent`，未知来源原样显示宿主给的值）以及它在跑还是在等，也可以直接「在对话中打开」。
- **数据来源**：`GET tasks` 多一个 `children` 字段——主会话的子会话（`parentSession` 等于主会话），按"在跑优先、再按 id"排序。工单执行器是工单自己的顶层会话，不会被算进这批。
- 采集方式值得记一笔：没有依赖 `agents.list()`（在插件的宿主上下文里拿不到），而是用插件自己在 `agent/created` 里见过的会话集合。代价是**只覆盖本进程加载过的会话**——重启前开过、之后没再打开的子会话不会出现。
- 单测：`runtime.spec` 覆盖「只报主会话的子会话、别家的不报、工单执行器不算」；`tasks.spec` 覆盖视图与路由字段；`canvas.spec` 覆盖两类卡片并存、分组计数、无标题子会话、未知来源原样显示。全量 1260 通过 / 6 个既有环境噪声。

- **工具级进度**：宿主监听 DSH 的 `tools/execute`（waterfall 事件），把"哪个会话在跑哪个工具、什么时候开始的"记成一棵只在内存里的表；`GET tasks` 里每张工单多一个 `tool: { name, since }`，主会话自己也有 `masterTool`。

## 0.2.10 — 2026-11-26

在 DSH `0.2.2-rc.5` 上执行器**干不了活**的根因找到了，并且画布发的文件现在真的能被打开。

- **修复：执行器（worker）拿不到任何工具。** 根因在我们自己的 `workOnly()`：它用 `scopeParentOf(agent)` 取允许的工具名，rc.5 里这个查找返回空，于是把一个**空的 allow-list** 交给 `tools.restrict()`——而空的 allow-list 不是"不限制"，是"把继承来的工具全藏起来"。执行器因此只剩插件自己的 `orchestrator_*`，读不了文件、跑不了命令。
  - 现在按 rc.5 的真实语义算白名单：`restrict` 只过滤**继承**的工具，会话自身作用域（预设挂载的）工具是豁免的、且**点名会报错**；所以先读父作用域、再读会话自身，两级都为空时**不下空名单**，改用按名字拒绝的守卫兜底。
  - 实测（隔离实例 + 真实模型）：worker 的 `bash` 跑出 `final-check` / `fix-verified`，退出码 0；schema 里 32 个名字，其中 `WORK_TOOLS` 的 18 个可调用，越界调用被拒并给出原因（`wait_agent` 实测：`An executor Session works with its ticket's tools only, not "wait_agent"`）。
- **修复：工单永远停在 `working`、worker 起不来或结束不了。** rc.5 把 `subagents` 服务换成了基于 projection/lifecycle 的新实现，我们依赖的 `waitForChildren` / `listChildren` / `drainChildren` 三个方法都不存在，于是收尾时抛 `TypeError: subagents.waitForChildren is not a function`（更早还表现为 `AggregateError: Stopping the background work ... failed`）。三者改为**可选**：宿主没有就视为没有子 agent 后台工作要等，工单正常收尾。
- **修复：工单结束后没有收回执行器工具。** 上一版把 `tools.guard()` 的返回值（注销器）当成检查函数再调用了一次，导致"工单已结束"的拒绝在兜底路径里恒为放行；现在把检查函数单独抽出，两处共用。
- **画布发的文件现在真的能被打开**：上传 → 路径随消息 → 主会话开单时把路径带给执行器 → 执行器 `read_image` 读取。实测让 worker 打开我上传的一张画布截图，它准确说出「主会话 / 任务 / 执行器」三列、图例文字与卡片内容。**注意链路是"文件 → 工单 → 执行器"**：主会话本身没有 `read`/`read_image`（它只有编排工具，这是设计如此），所以不勾选工单直接发给主会话的文件，主会话也读不了，只有它开出的工单能让执行器读。
- 单测：`runtime.spec.ts` 91 项全绿（含执行器/子 agent 的工具收窄、工单结束后的拒绝）；全量 1255 通过 / 6 个既有环境噪声（本机无 tmux ×5、一个 setup 断言）。

## 0.2.9 — 2026-11-25

在真正登录的页面里（另起的隔离实例，不碰你自己的实例）测出来的问题，以及画布发文件。

- **修复：主会话空闲时，画布/任务条提的问题永远没人回。** relay 一直用 `steer` 投递，而 `steer` 只把消息送进**正在跑的那一轮**，空闲会话不会被唤醒——于是消息排在队列里，`relay` 健康项还显示 `ready`，界面上看不出异常。实测：同一句话，`steer` 模式下 25 分钟没有任何反应；改成按会话状态选择后（空闲用 `followup`、运行中用 `steer`），5 秒内就开了一轮并回答。这个问题从 0.2.6 就存在。
- **画布 Composer 可以直接发给主会话了**：不勾选工单时，消息经新增的 `POST session/say` 送达主会话，由它决定开不开工单；勾选时仍是就那张工单提问。占位符与说明文案随之改正（此前写着“可直接发送”但按钮是禁用的）。
- **画布 Composer 支持发文件**：`＋` 选文件、直接粘贴截图、把文件拖进卡片都可以。文件由新增的 `POST uploads` 写进状态目录（`asks/<日期>/`，单文件 12 MB、每条消息最多 8 个），再随消息把**绝对路径**交给主会话。宿主只接受自己写出的路径，浏览器无法让主会话去打开 `/etc/passwd`。文字文件用 `read`、图片用 `read_image` 打开。
- **仍然阻塞（不是本插件能单独修的）**：在 DSH `0.2.2-rc.5` 上，主会话和执行器 Session **都拿不到文件/命令工具**——主会话只有 `orchestrator_*`，执行器也只有 `orchestrator_*`（实测原文：“This worker Session exposes only the orchestrator_* tools… no bash, filesystem-read, or read_image”）。所以文件虽然传上去了、路径也送到了，目前**没有 Session 能打开它**；同理，工单里的执行器也做不了实际工作。已确认不是权限或路径问题，也不是 `workOnly` 白名单把它过滤掉（试过父/自身两处都查，工具依然不存在），指向插件里的 `dsh-agent-preset` 内层插件在 rc.5 上未挂载，正在另查。
- 单测：`tests/uploads.spec.ts`（文件名净化、落盘、拒绝非法体、路径白名单、保留期、三条路由）、`tests/canvas.spec.tsx` 增加附件与“不勾选也发”的用例；`queue/health/followups` 三个 spec 按新的投递通道更新。

## 0.2.8 — 2026-11-25

在 Harness Dev（`~/.dsh-dev`，另起的独立实例）上第一次对着**真实页面**测任务条与画布之后的修正版。0.2.6、0.2.7 的页面行为此前只在 jsdom 里验证过，下面这些都是在真实页面里才暴露的。

- **修复 0.2.7 的任务条「提问」完全失效**：点「提问」没有任何反应、没有提示。宿主给的 `useInput` 是一个 **React Hook**（`useInput(selector)`，rc.5 自带的输入栏就是 `useInput(s => s)`），0.2.7 却在点击处理器里无参调用它，React 抛出 `Invalid hook call`（压缩后是 error #321），`ask` 在得出结果前被打断：既不发送，也不清空，也不提示。现在在组件体里以选择器形式调用，每次输入框变化都会重渲染，发问时读到的是当次渲染的最新状态。**0.2.7 的这一功能不可用，请升级。**
- **为什么测试没抓到**：测试里 `useInput` 的替身是一个普通函数，在哪里调用都不会出错。现在的替身（`tests/fixtures/panel.tsx` 的 `composerHook`）内部调用真实的 React Hook，在事件处理器里调用会像宿主一样抛 `Invalid hook call`；把旧写法放回去，6 个用例当场变红。`tests/installed-bundle.spec.tsx`（加载 profile 里实际安装的 `lib/client.js`）对 0.2.7 的失败也因此能复现。
- **画布第三列被挤出视口**：适配只量了卡片，空的泳道（还没有工单分到执行器时）不在范围里，三列的总宽超过视口也不会缩小。现在泳道作为画布的骨架一起量，并以它为适配范围。
- **图例盖住「主会话」泳道标题**：适配会把图例占的上边留出来（`fitView` 新增 `reserve` 参数，读图例底边）。
- **主会话卡片无条件带选中描边，小地图里是个黑块**：现在只有被勾选的工单才算选中；小地图画出泳道作底、卡片在上。
- **任务条头部**：计数现在紧跟标题（0.2.7 加提示语时把它挤到了句尾，成了一个没有标签的数字）；工单少时卡片撑满整行（`auto-fill` → `auto-fit`）。
- **画布的问答列表停在最旧的一条**，最新的回答被卡片底部盖住。现在新回答到达时列表跟到底部；你往上翻着看旧的时不会被拽回去。列表项的 key 也改成按整段对话里的位置，不再随「只取最近 4 条」而每次新增都变。
- 仍未做：任务条里的卡片会因执行器开始/结束而重排；画布上的相对时间不随时间刷新；「勾选一张待你处理的工单」在已勾选后仍显示。

## 0.2.7 — 2026-11-25

一次独立的 UI/UX 评审（读代码，未看运行中的页面）之后的修正版。没有新功能。

- **任务条不再可能覆盖你没发出去的话**：此前它靠槽位传入的输入框快照判断「输入框是否为空」，而那份快照是否随每次击键更新由宿主决定——如果是旧的，你正在写的话会被问题盖掉。现在优先用槽位提供的实时钩子 `useInput` 读，并且**读不到输入框状态时一律不发**（回一句说明），因为未知的输入框里可能有你的草稿。输入框在处理你输入的斜杠命令时也不发（此前会被说成「正在发送」）。
- **画布上的工单不再被截到 12 张**：此前宿主对任务条和画布都用同一个上限，第 13 张起在画布上直接看不见、也不提示。现在宿主返回全部未结束工单，由任务条自己只列前 12 张并计数「还有 N 个」。
- **提问连线画反了**：任务在中间一列、Composer 在左边，线却从任务的右缘出发再绕回来，穿过任务列。现在从面向目标的那条边出发。顺带修了 `edgePath` 里方向参数正负号语义自相矛盾的问题，以及两张卡贴得很近时控制点落到卡片外面的问题。
- **画布上的列表能滚动**：问答列表和输入框上的滚轮此前一律被拿去平移画布，最新的回答沉在列表下面看不到。现在这些地方各滚各的，⌘/Ctrl + 滚轮仍然是缩放。
- **打开画布时不再只对着空骨架适配**：此前只适配一次（那时还没有工单），真实工单到达后下面和右边的列跑到屏幕外。现在卡片增多时会重新适配，直到你手动平移或缩放过为止。
- 小处：拖动卡片时切走窗口不再让拖动「粘住」；卡片标题可以用键盘够到；没勾选工单时按 Enter 会提示「先勾选一张工单」；任务条在勾选前就说明勾选的用途，提交后有确认提示；英文文案统一用插件既有的 "Executor" 而不是 "Worker"。
- 仍未做（评审提出、留待有真实页面可看时再定）：图例遮住左上角的卡片标题；任务条里的卡片会因执行器开始/结束而重排；画布相对时间不随时间刷新。

## 0.2.5 — 2026-11-18

- **主会话可以直接管理自己创建的子级工作区了**：新工具 `orchestrator_workspaces`（`op=list|archive|delete`），此前这类清理只能靠桌面 UI 自动化（osascript 盲点 DevTools 控制台粘 IIFE，实测把脚本粘进了别的会话和侧栏终端）。
  - `op=list`：只列本插件为工单执行器创建的工作区（路径里带 `.dsh-superagent/work/` 的那些），带对应 ticket、每个 Session 的归档状态和仍在运行的工作（`turn`/`job`/`subagent`/`schedule` 按族列出）。
  - `op=archive`：按 DSH 客户端的归档语义写同一份 durable archive set——会话离开分组视图、日志保留；仍在跑的 Session 默认报成 `blocked`，`stop_active=true` 才先停再归档。
  - `op=delete`：**默认不删**，只返回「按 confirm 会发生什么」；`confirm=true` 时也只删这条**工作区注册**（目录与全部 Session 日志都在），且只要有 Session 在跑、或有 Session 尚未归档就拒绝。
  - 越界保护：不是子级工作区的路径（操作者自己的工作区）一律 `notChildWorkspace` 拒绝，`confirm` 也不放行。
- 主会话提示词加一条硬规则：子级工作区只用这些工具管，**不要走桌面 UI**。
- 模型可见面预算（`tests/model-surface.spec.ts`）59_000 → 60_500，只因为多了这一个工具；worker 面不变。
- 单测：`tests/workspaces.spec.ts` 覆盖路径标记、分页列表、归档集、无活跃会话/未归档/未确认三类拒绝；`tests/tools.spec.ts` 覆盖工具层接线与「默认不删」。

## 0.2.4 — 2026-11-09

## 0.2.0 — 2026-11-09

从 `hxh230802/dsh-superagent-prototype` 的 fork 收编进本仓库，并加上「本地工作区 + 主会话任务」两条不依赖 GitHub 的链路。

### 新增

- **本地工作区树 Source**（`src/sources/workspaces.ts`）：枚举本机工作区并监听其中文件活动，事件转 Trigger；根目录留空时自动接入 DSH 工作区树，显式配置时只盯配置目录。带嵌套去重与「排除 DSH 家目录 / 插件状态目录」的自激保护。
- **主会话任务 Source**（`src/sources/session.ts`）：操作者在主 Session 里直接下达的任务；由 `Engine.operatorTask` 直通授权（不需要发送者名单或准入表），每个任务开一张工单。
- **主会话工具 `orchestrator_task`**（`src/app/tools/main.ts`）：主 Session 按操作者的任务开单，提示词同步说明「不要自己动手」。
- **工单执行落点**（`src/executor/dsh.ts`）：触发携带 `workspaceRoot` 时，工单目录为 `<工作区>/.dsh-superagent/work/<工单>`；否则沿用配置的执行根。
- 面板：来源页展示新 Source 健康状态；「本地工作区树」设置里可用「刷新工作区列表」拉取本机工作区（kind 写入 Source KV labels）。

### 变更

- 面板设置页的工作区下拉需要 kind 自己持久化 labels；`refreshLabels` 现在会写入。
- 新增健康码与中英文案：`sessionReady`、`workspaceNoRoots`、`workspaceRootMissing`、`workspaceWatching`。
